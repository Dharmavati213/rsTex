# The differences from the second oracle: the pdfTeX of the official TeX Live 2026 for x86_64-linux, which is what CI's Linux job compares with, through RSTEX_ORACLE_DIR.  run.py reads this
# only then, in place of known_divergences.txt.  A line is the case, what is allowed, and why.
#
#   differs:-N+M:HASH   The case differs, and these are all its differences.  Each log, terminal, PDF object and dvitype line is compared; HASH covers what lies between the first and the last line that
#                       differ, N lines of the oracle's and M of the candidate's, with TeX's wrapping and the tree's place taken out.  Any other difference, or none, fails: the failure prints what it is now.
#   random:-N+M:HASH    The same, or it agrees.  For an oracle that gives two answers on one input.
#   dies:SIGNAL         The oracle dies by this signal, and the candidate ends by itself.  There is nothing to compare past that.
#
# These lines are about that one build, and which side of these rstex should take is a decision still to be made.  Where a line has W, M, S or O alone, rstex gives what Arch's pdfTeX gives on the same
# tree, and that comparison stays exact in the ordinary run of this tool.  Each was seen by running both binaries on both trees.
#
# W, the width of integer.  Arch configures with --disable-dump-share, which defines NO_DUMP_SHARE, so w2c/config.h makes integer and scaled a long, and the official build does not, so they are an int.
#     So on the official pdfTeX a sum past 2^31 wraps, which is signed overflow in C, and on Arch's it does not.  Each needs numbers past 2^31: 32768pt in sp, or \count or demerits of that size.
# M, the memory word.  The same choice makes the word 8 bytes there and 16 on Arch's, so a word read before it was written holds something else.
# S, the source.  Arch's build applies upstream's b50e042b to tex.ch, of 2026-04-20, after the TeX Live 2026 tag: scan_file_name no longer skips a \relax in front of a name.
# O, an uninitialised read in pdfTeX itself.
#
